## 6.2.1. Платформа, БД, RLS, тестовая база

_Подгруппа **B1** · 4 задачи._

### BE-00 · Каркас backend

**Зависит:** —
**Объём:** pyproject (uv), FastAPI, pydantic-settings, ruff, mypy, `/health`+`/readyz`, Dockerfile, Makefile.
**AC:**
- [ ] `make run` поднимает API, `/health` → 200, `/readyz` проверяет БД.
- [ ] Линтеры/типы зелёные в CI.
- [ ] Секреты только через env, `.env.example` актуален.

### BE-01 · Middleware и обработка ошибок

**Зависит:** BE-00
**Объём:** `X-Request-Id`, резолвинг тенанта, `SET LOCAL app.tenant_id`, обработчик ошибок → problem+json, access-log JSON.
**AC:**
- [ ] Неизвестный Host → 404 `tenant_not_found`.
- [ ] Любая ошибка содержит `code` и `trace_id`; 500 не отдаёт стектрейс.
- [ ] Логи связаны `request_id`.

### BE-02 · Базовые модели, миграции, RLS

**Зависит:** BE-01
**Объём:** миграция 0001: extensions (`citext`, `pgcrypto`, `btree_gist`), `tenant`, `user`, RLS-политики, роли БД.
**AC:**
- [ ] Запрос без `app.tenant_id` не возвращает данные (RLS).
- [ ] `alembic upgrade head` на чистой БД работает; downgrade не ломает.

### BE-03 · Тестовая инфраструктура

**Зависит:** BE-02
**Объём:** pytest-asyncio, фикстуры тенантов/пользователей/токенов, polyfactory, изолированные транзакции, CI-сервис Postgres.
**AC:**
- [ ] Тест «тенант A не видит данные тенанта B» проходит.
- [ ] Тесты не зависят от порядка и общего состояния.
- [ ] Покрытие ядра ≥ 80% (без учёта сгенерированного).

## 6.2.2. Аутентификация, роли, 2FA

_Подгруппа **B2** · 6 задач._

### BE-AUTH-01 · Регистрация и модель пользователя

**Зависит:** BE-02, BE-03
**Объём:** таблицы `user`, `refresh_session`, `password_reset_token`, `user_mfa`; `POST /auth/register`; argon2id; email `citext` уникален в тенанте.
**AC:**
- [ ] Дубль email → 409 `email_taken`; нормализация регистра.
- [ ] Пароль < 8 символов → 422 с `fields`.
- [ ] Создаётся только роль `user`; `verification_status` = `pending`.

### BE-AUTH-02 · Логин, refresh, логаут

**Зависит:** BE-AUTH-01
**Объём:** `POST /auth/{login,refresh,logout}`, cookie `__Host-rt`, ротация и reuse detection.
**AC:**
- [ ] Повторное использование старого refresh → 401 `session_revoked` + отзыв сессии.
- [ ] Cookie имеет `HttpOnly/Secure/SameSite=Lax`.
- [ ] Access живёт 15 мин, перевыпуск без потери сессии.

### BE-AUTH-03 · 2FA (TOTP)

**Зависит:** BE-AUTH-02
**Объём:** `POST /auth/mfa/{setup,confirm,verify}`; recovery-коды; обязательность для `owner`/`admin`.
**AC:**
- [ ] Без подтверждённого MFA owner/admin не получает access.
- [ ] Recovery-код одноразовый; 10 кодов, хранятся хешами.
- [ ] 5 неверных попыток/5 мин → блокировка (`rate_limited`).

### BE-AUTH-04 · RBAC и `/auth/session`

**Зависит:** BE-AUTH-03
**Объём:** `get_current_user`, `require_permission`, `GET /auth/session` (user, tenant, role, `permissions[]`, `verification_status`, `offer_accepted`).
**AC:**
- [ ] Каждая строка матрицы §3.3 покрыта тестом (403 `forbidden_role`).
- [ ] `permissions[]` соответствует роли и используется FE для скрытия UI.

### BE-AUTH-05 · Сброс пароля

**Зависит:** BE-AUTH-01
**Объём:** `POST /auth/password/{forgot,reset}`, токен 1 ч.
**AC:**
- [ ] `forgot` всегда 202 (нет enumeration).
- [ ] После сброса все refresh-сессии отозваны.

### BE-AUTH-06 · Rate limit аутентификации

**Зависит:** BE-AUTH-02
**Объём:** in-process лимитер (IP+email), `Retry-After`, метрика.
**AC:**
- [ ] 10 логинов/мин/IP → 429 `rate_limited`.
- [ ] Лимит конфигурируется через env.
- [ ] Ограничение задокументировано как single-instance (см. §10).

## 6.2.4. Каталог, файлы, доступность

_Подгруппа **B4** · 11 задач._

### BE-CAT-01 · Категории

**Зависит:** BE-AUTH-04
**Объём:** CRUD + архивация, `slug` (unique per tenant), `version`, публичный список.
**AC:**
- [ ] Архивная категория скрывает свои лоты из публичного каталога.
- [ ] Slug уникален и валидируется (`^[a-z0-9-]+$`).
- [ ] PATCH без `version` → 422; устаревший → 409 `stale_version`.

### BE-CAT-02 · Характеристики категории

**Зависит:** BE-CAT-01
**Объём:** bulk `PUT`, типы `number|text|select`, `code` immutable, `unit`, `is_required`, `options`, `is_archived`.
**AC:**
- [ ] Смена типа при существующих значениях → 409 `characteristic_in_use`.
- [ ] Удаление = архивация; значения сохраняются в `lot.characteristics`.
- [ ] Порядок (`sort`) сохраняется; фильтры публичного каталога строятся из активных.

### BE-LOT-01 · CRUD лотов

**Зависит:** BE-CAT-02, BE-FILE-01
**Объём:** создание/чтение/правка, валидация характеристик по определениям, фото, модель и цена, `slug`, `version`.
**AC:**
- [ ] Значение характеристики не того типа → 422 с путём поля.
- [ ] Обязательные характеристики пустыми не сохраняются.
- [ ] Цена > 0; `daily` требует шаг ≥ 1 дня.

### BE-LOT-02 · Статусы лота

**Зависит:** BE-LOT-01
**Объём:** `POST /admin/lots/{id}/status` + guards, audit.
**AC:**
- [ ] `archived` при активной брони/аренде → 409 `lot_has_active_rental`.
- [ ] `maintenance` создаёт occupancy-блок и недоступен для брони.
- [ ] `overdue` нельзя выставить вручную (только система/закрытие).

### BE-LOT-03 · Массовое создание

**Зависит:** BE-LOT-01
**Объём:** `POST /admin/lots/bulk` (шаблон + count 1–50), Idempotency-Key.
**AC:**
- [ ] Всё или ничего: ошибка по одному лоту откатывает пачку.
- [ ] Имена/слаги уникальны (`Модель №1…№N`).
- [ ] Повтор с тем же ключом не создаёт дублей.

### BE-LOT-04 · Публичный каталог и карточка

**Зависит:** BE-CAT-02
**Объём:** `GET /public/{categories,lots,lots/{slug}}`, фильтры `char_<code>`, доступность в периоде, ETag/кэш.
**AC:**
- [ ] Возвращаются только `active` лоты; карточка `maintenance/archived` → 404.
- [ ] Неизвестный фильтр → 422; значения фильтров валидируются.
- [ ] ETag/304 работает; ответ ≤ 1 с на 3G-профиле (100 лотов).

### BE-FILE-01 · Загрузка файлов

**Зависит:** BE-TEN-01
**Объём:** `POST /files` multipart, `purpose`, проверка magic-bytes, лимиты, S3 (public/private), подписанные URL, `attachment`, очистка orphan.
**AC:**
- [ ] Несовпадение MIME и содержимого → 422 `upload_invalid`.
- [ ] Чужой `file_id` при привязке → 404.
- [ ] EXIF удаляется из фото; документы только в приватном бакете.

### BE-AVA-01 · Модель занятости

**Зависит:** BE-LOT-02
**Объём:** таблица `occupancy`, EXCLUDE-constraint, сервис `reserve/release`, миграция, маппинг `IntegrityError` → 409.
**AC:**
- [ ] Параллельные вставки пересекающихся интервалов → ровно одна успешна (тест на гонку).
- [ ] `release` идемпотентен; история сохраняется.
- [ ] Constraint проверен на границах `[start, end)` (смежные интервалы разрешены).

### BE-AVA-02 · Публичная доступность

**Зависит:** BE-AVA-01
**Объём:** `GET /public/lots/{slug}/availability`, `GET /public/availability`, `next_free`.
**AC:**
- [ ] Гость не получает персональных данных и `kind` кроме `busy`.
- [ ] Диапазон > 90 дней → 422.
- [ ] p95 ≤ 150 мс на 100 лотах (индексы по `lot_id`, `period`).

### BE-AVA-03 · Календарь админа

**Зависит:** BE-AVA-01
**Объём:** `GET /admin/calendar`, `GET /admin/lots/{id}/calendar` с источником занятости и кратким rental.
**AC:**
- [ ] Ответ содержит `kind` + `rental_id`/`block_id` + статус аренды.
- [ ] Фильтры по категории/лоту/статусу; лимит 200 лотов → 422 при превышении.
- [ ] `no-store` в заголовках.

### BE-AVA-04 · Ручные блокировки

**Зависит:** BE-AVA-01
**Объём:** `POST /admin/lots/{id}/blocks`, `DELETE /admin/lots/{id}/blocks/{block_id}`, audit.
**AC:**
- [ ] Блокировка поверх аренды → 409 `slot_taken`.
- [ ] Причина 3–200 символов обязательна.
- [ ] Удаление освобождает интервал для новых броней.

### BE-BOOK-04 · Админ-аренды и закрытие

- [ ] Повторный прогон не дублирует уведомления и audit.
- [ ] 10 000 аренд обрабатываются < 30 с (нагрузочный тест).
- [ ] Аренда, отменённая между выборкой и обновлением, не переходит (проверка статуса в `WHERE`).

### BE-WRK-03 · Напоминания об окончании

**Зависит:** BE-WRK-02, BE-NOT-05
**Объём:** джоба за `reminder_hours_before` до `end_time`, дедуп по outbox-ключу.
**AC:**

### BE-WRK-04 · Прочие джобы

**Зависит:** BE-WRK-02
**Объём:** эскалация `overdue > 24 ч`, возврат лота из `maintenance` по окончании блока, очистка orphan-файлов (24 ч), TTL `idempotency_key`, purge документов верификации по ретеншену.
