# Изменения требований (change requests)

> Навигация: [README](../../README.md) · [Задачи MVP](../tasks/README.md) · [Контракт](../contract/README.md) · [Поставка](../delivery.md)

Правки заказчика живут **отдельно** от исходного плана MVP: `docs/tasks/*` не переписывается, изменения
описываются своим набором задач и своим гейтом. Так видно, что именно добавилось к согласованному объёму.

Правила:

| # | Правило |
| - | ------- |
| R-1 | CR не правит `docs/tasks/*`; он ссылается на существующие ID и расширяет их |
| R-2 | Если задача из CR полностью замещает задачу MVP — это явно указано в колонке «Замещает» |
| R-3 | Контракт, mock и фронтенд идут в одной поставке (frontend-first на моке) |
| R-4 | Backend-задачи CR остаются в этом же документе, пока контракт не переехал в Pydantic |

## Индекс

| CR | Название | Источник | Срез | Статус |
| -- | -------- | -------- | ---- | ------ |
| [CR-01](cr-01/README.md) | Тарифы «от», варианты 1/2 АКБ, остатки АКБ, блокировки и график «лоты × дни» | 7 голосовых заказчика (транскрипт `tasks.md`) | S1–S3 (мок + фронтенд), S4 (backend) | S1–S3 сданы; S4 — backend |
