# CR-01 · Тарифы «от», варианты АКБ, остатки, блокировки и график

> Навигация: [README](../../../README.md) · [Задачи MVP](../../tasks/README.md) · [Изменения](../README.md) · [Контракт](../../contract/README.md)

**Статус:** S0–S3 сданы — контракт, мок и фронтенд (`MOCK-01…03`, `FE-CAT-03`, `FE-BOOK-04`, `FE-LOT-05`, `FE-CAL-04`, `FE-ADM-04`).
Открыты S4 (backend по контракту), сквозной `QA-BOOK-02` и `DOC-01` (ТЗ и `use-cases.md`).
**Источник:** 7 голосовых сообщений заказчика (транскрипт — `tasks.md` в корне, не в git).
**Затрагивает:** витрину каталога, карточку/диалог брони, админ-форму лота, админ-календарь аренд, контракт, мок.
**Не затрагивает:** верификацию, тикеты, аналитику, уведомления, биллинг.

## 1. Что меняется по сравнению с планом MVP

| Было в MVP | Стало в CR-01 |
| ---------- | ------------- |
| Цена — один скаляр `lot.price_minor`, расчёт линейный `цена × часы/дни` | Тарифные тиры на **варианте** лота: `variants[{battery_count, price_tiers}]`; цена считается сервером, витрина показывает «от» |
| Аккумуляторы — отдельные лоты категории «Аккумуляторы» | Аккумуляторы — **пул тенанта** (`battery_stock`), лот ссылается на тип; аренда занимает `battery_count` штук на интервал |
| Срок аренды задаётся моделью лота (`hourly`/`daily`) | Дополнительно `allowed_durations` на лот: админ решает, доступны ли сутки/3 дня/неделя/месяц |
| Блокировка лота — только статусом (`maintenance`/`archived`) | Плюс блоки на конкретные интервалы, точность — сутки в TZ тенанта |
| Админ-календарь: день/неделя (24-часовой таймлайн) и классическая месячная сетка | Основной вид — **гант «лоты × дни месяца»**, часовой таймлайн остаётся вторичным |
| Часовой режим — равноправная модель | Часовой режим не развиваем, но `rental_unit: hour` остаётся в контракте |

## 5. Границы scope

- Часовой режим не развиваем: остаётся только `rental_unit: hour` для лотов, которым он реально нужен.
- Промокоды, скидки, биллинг SaaS — по-прежнему бэклог (`UC-12.4`), CR их не поднимает.
- Аналитика не меняется: `rental.price_minor` уже фиксируется на брони; разрез по вариантам — по отдельному запросу.
- Пакетная схема «неделя + остаток дней» не делается: вместо неё round-up по D-20.

## 6. Гейты

Каждый срез считается сданным, когда:

1. `pnpm gen:api && pnpm typecheck && pnpm lint && pnpm test` зелёные в `frontend/`.
   Для **S0** (контракт без мока и UI) действует только `pnpm gen:api`: `typecheck` остаётся красным до S1,
   потому что фронтенд ещё читает удалённые `price_minor`/`rental_model`; это ожидаемое состояние, а не регрессия.
2. Ручной сценарий среза пройден в `pnpm dev:full` (браузер, не только тесты).
3. `docs/changes/cr-01/*` обновлён: чек-боксы AC закрыты, спорные места — в `decisions.md`.
4. Для S4 — векторы цены из `decisions.md` совпадают на моке и на backend.
