# Решения контракта: CR-01 (D-19…D-26)

> Контракт: [README](README.md) · [openapi.json](openapi.json) · [pricing.md](pricing.md) · [endpoints.md](endpoints.md)
> Базовые решения D-01…D-18 остаются в [`../docs/contract/README.md` §3](../docs/contract/README.md) до переезда
> источника правды в Pydantic (CT-01/CT-03). Этот файл дополняет их решениями CR-01; при переезде D-19…D-26
> переносятся в общий реестр без изменения текста.

Источник каждого решения — номер голосового сообщения заказчика из [трассировки](../docs/changes/cr-01/README.md#2-трассировка-сообщение-заказчика--задачи).

| ID | Решение | Источник |
| -- | ------- | -------- |
| D-19 | Тариф живёт на варианте лота: `lot.variants[{battery_count, price_tiers}]`, тир — `{min_units, price_per_unit_minor}`. Единица срока — `lot.rental_unit` (`day` или `hour`). Поле `rental_model` удалено | 1, 2 |
| D-20 | Цена периода: тир с наибольшим `min_units ≤ units`; итог `units × price_per_unit`; цена ограничивается стоимостью любого более длинного пакета (round-up). Алгоритм и векторы — [pricing.md](pricing.md) | 1 |
| D-21 | Неделя = 7 единиц, месяц = 30 единиц; календарная арифметика 28/31 день не используется | 1 |
| D-22 | Витрина показывает `Lot.price_from` — минимум `price_per_unit` по активным вариантам и тирам, с `at_units` и `battery_count`; подпись обязательна при `at_units > 1` | 1 |
| D-23 | Ёмкость АКБ: в любой момент интервала сумма `battery_count` пересекающихся аренд одного `battery_type` ≤ `battery_stock.quantity`. Проверка в одной транзакции с созданием аренды | 3 |
| D-24 | Блок ставится на целые сутки в TZ тенанта, интервал `[start, end)`. Блок не расходует АКБ и не влияет на другие лоты | 4 |
| D-25 | Разрешённые сроки — на лот: `allowed_durations: number[]` в единицах `rental_unit`, по возрастанию и без дублей. Разрешён любой срок ≥ минимума списка; пресеты — элементы списка. Валидация серверная | 4 |
| D-26 | Часовой режим — только `rental_unit: hour`; отдельного UI-сценария CR не добавляет | 5, 6 |

## D-19 и D-20: цена и варианты

- `variants` — обязательный непустой массив; `battery_count` уникален в пределах лота.
- При `battery_count > 0` обязателен `battery_type`; при `battery_count = 0` тип может быть `null`.
- `price_tiers` непустой, `min_units` возрастают, `price_tiers[0].min_units == min(allowed_durations)`.
- Цена за единицу не возрастает при росте `min_units` — иначе длинная аренда дороже короткой.
- Клиент цену не считает: только `price_from` (витрина) и `Quote.variants[].price_total_minor` (диалог брони).
  Цена аренды замораживается в `rental.price_minor` и не меняется при последующей правке тарифов.
- `PATCH /admin/lots/{id}` требует `version`; несовпадение → `409 stale_version`, ответ содержит новый `version`.
- `category_id` и `photos`/`characteristics` не меняются по смыслу CR; в PATCH они допустимы, чтобы форма
  сохраняла лот целиком.

## D-21 и D-22: сроки и «от»

- Округление длительности вверх: 23 часа на суточном лоте — 1 сутки; 1 сутки 1 час — 2 суток.
- `price_from` не хардкодится: сервер пересчитывает его при выдаче `GET /public/lots`, `GET /public/lots/{slug}`
  и `GET /admin/lots`.
- Точные цены по срокам на витрине не показываются — только `price_from` и подпись с условием
  («при аренде от 7 суток, 1 АКБ»). Выбор срока и варианта живёт в диалоге брони.

## D-23: ёмкость аккумуляторов

Пик занятости типа считается по событиям `start (+k)` / `end (−k)` для аренд в статусах `booked`/`active`.
Новая бронь проходит, если пик после добавления ≤ `battery_stock.quantity`; иначе `409 battery_unavailable`.
Уменьшение `quantity` ниже `peak_committed` → `409 stock_below_committed` с числами в `detail`.
Блоки и `maintenance` ёмкость не расходуют. Порядок проверок: слот лота → ёмкость АКБ.
Формула, пример и тест-кейсы — [pricing.md §7](pricing.md).

## D-24: блоки

- Блок ставится на целые сутки в TZ тенанта; UI выбирает дни, не время.
- Пересечение с `booked`/`active` → `409 slot_taken`.
- Причина обязательна, 3–200 символов.
- Блок виден в `GET /admin/schedule` и в публичной доступности; удаление сразу освобождает дни.
- Статус `maintenance` остаётся «бессрочным блоком» и не дублируется записями `lot_blocks`.

## D-25 и D-26: сроки и часы

| Настройка | Что видит пользователь |
| --------- | ---------------------- |
| `[1, 3, 7, 30]` | чипы «1 день / 3 дня / Неделя / Месяц», свой срок от 1 |
| `[7, 30]` | «Неделя / Месяц», свой срок от 7 |
| `[30]` | «Месяц», свой срок от 30 |

`units < min(allowed_durations)` → `422 rental_period_not_allowed` независимо от UI.
Часовой лот (`rental_unit: hour`) не получает special-case в `schedule` и в расчёте цены: работают те же D-20/D-25.

## Коды ошибок, добавленные CR-01

| Код | HTTP | Где | Текст для UI |
| --- | ---- | --- | ------------ |
| `rental_period_not_allowed` | 422 | `POST /rentals`, `quote` | «Минимальный срок аренды — 7 дней» |
| `battery_unavailable` | 409 | `POST /rentals`; `quote.variants[].unavailable_reason` | «Свободных аккумуляторов на эти даты нет» |
| `stock_below_committed` | 409 | `PATCH /admin/batteries/{battery_type}` | «Нельзя уменьшить: 12 шт. уже забронированы» |
| `slot_taken` | 409 | блоки, `POST /rentals` | «В эти дни лот занят» (переиспользуется) |
| `stale_version` | 409 | `PATCH /admin/lots/{id}` | «Лот изменён другим администратором» (переиспользуется) |

Клиент различает ошибки по `Problem.code`, не по `detail` (D-17).

## Миграция существующих данных

| Было | Стало | Правило |
| ---- | ----- | ------- |
| `rental_model: hourly` | `rental_unit: hour` | 1:1 |
| `rental_model: daily/custom` | `rental_unit: day` | `custom` больше не отдельный режим |
| `price_minor: N` | `variants: [{battery_count: 1, price_tiers: [{min_units: 1, price_per_unit_minor: N}]}]` | 1:1, цена суточных лотов не меняется |
| `allowed_durations` отсутствует | `[1]` | лот продолжает продаваться посуточно |
| `battery_type` отсутствует | `null` | для лотов категории «Аккумуляторы» — по коду характеристики, иначе вручную |

Лоты-аккумуляторы остаются лотами и получают `battery_type`, чтобы не ломать каталог; перенос их количества
в `battery_stock` — вне CR.
